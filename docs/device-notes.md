# Заметки по устройствам

## KENSHI E11 (стенд разработки)

Android 13 (API 33), MediaTek MT8781, 1200×2000 @ 240 dpi (500×833 dp — `smallestWidth` всего 500 dp, поэтому «планшет» определяется ещё и по физической диагонали ≥ 7″: `isTabletDevice`; вибрация по умолчанию **выключена**), вибромотор без amplitude control. Планшет стоит горизонтально; `adb connect 192.168.0.16:5555`.

### Аудио-источник (T-040)

| Параметр | Значение |
|---|---|
| `PROPERTY_SUPPORT_AUDIO_SOURCE_UNPROCESSED` | `false` — UNPROCESSED не задекларирован, в режиме «авто» приложение берёт `VOICE_RECOGNITION` |
| Открытый источник | `VOICE_RECOGNITION`, 48 000 Гц, float mono |
| Буфер `AudioRecord` | `getMinBufferSize × 4` = 3840 сэмплов (80 мс) |
| Индикатор в настройках | «обработка не гарантирована» |

Ручной выбор `UNPROCESSED` на E11 возможен (источник открывается), но по документации Android незадекларированный UNPROCESSED ведёт себя как `DEFAULT` — в приложении он помечен «не проверена». Сравнение спектров UNPROCESSED vs VOICE_RECOGNITION со свипом — **не сделано** (нужна тихая комната и свип с мониторов; см. ниже).

### Пайплайн и задержка (T-041)

- Обработка одного кадра (2048/480) на E11 — задержка «конец чанка → метрика» 1–5 мс (лог `CupolaAudio: stats`).
- Полный путь микрофон → метрика оценивается как чанк 10 мс + задержка HAL (десятки мс) + обработка ≈ 40–60 мс. Акустический замер «щелчок → отметка» **не делался**; при необходимости — щелчок с мониторов и сравнение времени по логам.
- 10‑минутный прогон — см. раздел «Стабильность».

### Вибрация (T-057)

`hasAmplitudeControl = false` → импульсный режим (40 мс, период `600 − 500·score`). Физически не проверялась (планшет стоит на столе; при включении вибрации проверить, не попадает ли она в микрофон — см. предупреждение в онбординге).

### Экраны

- Портрет и ландшафт — всё рабочее содержимое влезает без прокрутки.
- Лог/лин шкала, окно 2048/4096, источник — переключаются без перезапуска приложения (движок перезапускается сам).
- Foreground-service: при сворачивании в сессии микрофон работает, уведомление «Купол · Купол слушает · <нота> · Стоп» в шторке, `isForeground=true`.

## Раунд 3 (2026‑09‑15): записи, трекер, телефонная эмуляция

- Планшет теперь по USB: серийник `DJW429008036` (`export ANDROID_SERIAL=DJW429008036 CUPOLA_DEVICE=DJW429008036`); Wi‑Fi `192.168.0.16:5555` то offline, то online — не полагаться. `adb tcpip 5555` по USB роняет устройство из VM.
- Прослушивание записей: mp3 → `gst-launch-1.0 … ! wavenc` → нарезка python `wave` → `aplay -q file.wav` (дефолтное устройство; явный `plughw:1,0` играл слишком тихо). Скриншоты бёрстом `adb exec-out screencap -p` с шагом 0,35–0,4 с, склейка PIL.
- Офлайн-трасса трекера на том же WAV (без микрофона): положить файл в `audio-samples/` (в `.gitignore`, rsync его переносит), на сервере `CUPOLA_TRACE_WAV=/root/cupola/audio-samples/x.wav ./gradlew -q :core-dsp:test --tests '*.WavTraceTest' --rerun-tasks`, вывод — в `core-dsp/build/test-results/test/TEST-…WavTraceTest.xml` (`system-out`). Формат строки: `T t yin f0/conf -> out/conf trk hz/strength decision rN | cand:score/count …`.
- Через мониторы (комната + микрофон E11) спектр отличается от файла: на Хворостовском 5:20 трекер на планшете иногда уходит на 4‑ю гармонику (~1160 Гц, D6), хотя офлайн на файле этого нет. Debug-сборка пишет ту же трассу в logcat (`adb logcat -s CupolaTrace`).
- Доля/возвышение через мониторы: доля 15–50 %, возвышение +10…+24 dB — сильно выше синтетики; пороги по умолчанию (12 % / 6 dB) подобраны по синтетическому голосу и ждут настройки на живом голосе.
- Телефонная вёрстка проверялась эмуляцией на E11: `adb shell wm size 720x1600 && adb shell wm density 320` (360×800 dp), ландшафт — `settings put system accelerometer_rotation 0` + `user_rotation 1`; возврат — `wm size reset`, `wm density reset`, `accelerometer_rotation 1`. Найдено и исправлено: шестерёнка обрезалась, легенда спектра наезжала на подпись, значения строк настроек ломались по буквам, в ландшафте зона ноты не помещалась.

## OnePlus CPH2747 (Android 16): тишина при запуске (2026‑09‑16)

Журнал микрофона 0.2.10 показал: `perm=true appop=allowed importance=100 audioMode=0`, но наша запись `silenced=true` десятки секунд, а в системе параллельно активна чужая запись `src5` (`CAMCORDER`), начатая раньше нашей. `CAMCORDER` — «приватный» источник: по политике Android (sharing audio input) он получает звук, обычная запись — нули, даже если её приложение на экране. Смена UNPROCESSED ↔ VOICE_RECOGNITION не помогала. Лечение с 0.2.11: `AudioRecord.Builder.setPrivacySensitive(true)` — между двумя приватными записями звук у начавшей последней. Какое приложение держит `CAMCORDER`, система не сообщает.
