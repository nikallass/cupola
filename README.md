# Купол (Cupola)

[![build](https://github.com/nikallass/cupola/actions/workflows/build.yml/badge.svg)](https://github.com/nikallass/cupola/actions/workflows/build.yml) · [English](README-EN.md)

Офлайн Android-визуализатор вокальной тренировки: спектрограмма, нота и отклонение в центах, обертоны и «звон» — певческая форманта около 2,4–3,6 кГц. Звон оценивается по доле энергии голоса в полосе купола и по её возвышению над соседними частотами, а не по громкости. В игровом режиме за удержание звука «в куполе» начисляются очки. Без облака и телеметрии: аудио не покидает устройство.

**Установка:** APK последнего релиза — на странице [Releases](https://github.com/nikallass/cupola/releases). Нужен Android 8.0+ и разрешение на установку из неизвестных источников. Релизы подписаны постоянным ключом, новые версии ставятся поверх старых.

**Это не медицинский инструмент и не замена преподавателю.** Приложение показывает, что произошло со звуком, и не даёт технических вокальных инструкций. Если горло устало или болит — прекратите занятие независимо от очков.

Документы: `SPEC.md` (спецификация; §15 — решения по версиям), `RESEARCH.md` (научная база), `TICKETS.md` (план работ), `docs/device-notes.md` (что проверено на устройствах), `CHANGELOG.md`.

## Что умеет

- **Нота.** Русское и международное имя, отклонение в центах на шкале ±50 ¢, частота, число обертонов, вибрато / качание / тремоло (границы настраиваются). Показания сглажены, нота удерживается при коротких срывах детектора.
- **Купол.** Дуга заливается с двух сторон к вершине; внутри — доля энергии в полосе, под дугой — возвышение в dB. Когда половинки смыкаются, вершина искрится, начисляются очки и срабатывает виброотклик.
- **Цель и «Дать тон».** Ноту можно закрепить тапом или выбрать из списка; кнопка «Дать тон» играет её фортепианным звуком. Строй A4 и подстройка в центах — в настройках.
- **Спектрограмма.** Логарифмическая или линейная шкала, лента купола, трек высоты, линии закреплённой ноты и её обертонов, регулируемый контраст. Окно по времени меняется щипком от 2 до 30 с; на паузе буфер 60 с листается назад.
- **Спектр.** Сглаженный во времени спектр с линиями и номерами гармоник и линией фонового шума.
- **Фоновый шум** считается сам — по тихим паузам между фразами за последние несколько минут (по умолчанию 3) — и вычитается из спектра, чтобы шум не давал очков и не прятал купол.
- **Игровой режим.** Плавающая кнопка со звездой запускает игру: очки, серии, подсказки, итоги; время и очки видны в заголовке зоны «Нота». Игра продолжается в фоне с уведомлением. Режим можно выключить.
- **Интерфейс.** Полноэкранный режим; зоны сворачиваются тапом по заголовку; плавающие кнопки паузы и настроек бледнеют, пока их не трогают. Портрет и ландшафт, телефоны и планшеты, светлая и тёмная темы, русский и английский.
- **Диагностика.** «Сохранить лог» в тонких настройках записывает журнал приложения в файл.

## Требования

- Android 8.0+ (API 26). Целевое устройство разработки — планшет KENSHI E11 (Android 13).
- Микрофон. Источник аудио `UNPROCESSED` (если устройство его декларирует), иначе `VOICE_RECOGNITION`; шумоподавление и AGC принципиально не включаются. Если система поначалу отдаёт тишину, приложение само переоткрывает микрофон.

## Сборка

Kotlin + Jetpack Compose, Gradle KTS, JDK 17, Android SDK 35 (platform 35, build-tools 35.0.0).

```
./gradlew :app:assembleDebug            # APK: app/build/outputs/apk/debug/app-debug.apk
./gradlew :app:assembleRelease          # release без минификации; подпись — см. «Релиз»
./gradlew :core-dsp:test                # тесты DSP на синтетике (чистый JVM)
./gradlew :core-dsp:test --tests "*.PitchTest"
./gradlew check                         # тесты + проверка, что JVM-модули не импортируют android.*
```

Модули: `:app` (UI, DI, сессия, сервис, гаптика, настройки), `:core-audio` (AudioRecord, ring buffer, движок), `:core-dsp` (FFT, pitch, метрики, фоновый шум, скоринг — чистый JVM), `:core-notation` (ноты, октавы, центы — чистый JVM), `:core-testdata` (синтетические сигналы для тестов).

### Цикл «правка → сборка на сервере → планшет»

Рабочая машина разработчика — arm64-VM, под которую AAPT2 не поставляется, поэтому сборка идёт на x86_64-сервере, а установка — на планшет по `adb` в локальной сети:

```
scripts/deploy.sh              # rsync → сервер → assembleDebug → APK в build/ → adb install → запуск
scripts/deploy.sh --test       # только JVM-тесты (:core-dsp, :core-notation) на сервере
scripts/deploy.sh --check      # gradlew check: тесты + защита от android.* в JVM-модулях + lint
scripts/deploy.sh --release    # assembleRelease → build/cupola-release.apk
scripts/deploy.sh --no-install # собрать и скачать APK, не ставить
scripts/deploy.sh --logcat     # после запуска показать logcat приложения
scripts/deploy.sh --test -- --tests "*.PitchTest"   # проброс аргументов Gradle
scripts/tap.sh "Старт"         # тап по элементу UI планшета (для автономных проверок)
scripts/tones.py build/tones   # тестовые тоны для мониторов (aplay build/tones/saw220.wav)
```

Адреса сервера/планшета задаются переменными окружения `CUPOLA_SERVER`, `CUPOLA_SSH_KEY`, `CUPOLA_REMOTE_DIR`, `CUPOLA_DEVICE` (значения по умолчанию — в начале скрипта).

| Цикл (тёплый Gradle-демон) | Время |
|---|---|
| правка → приложение запущено на планшете | ~45–60 с |
| `--test` | ~10–50 с |
| `--check` | ~60 с |
| первый запуск (загрузка Gradle, SDK-компонентов, зависимостей) | ~5 мин |

## Релиз

GitHub Actions (`.github/workflows/build.yml`): на каждый push и PR — `gradlew check` (тесты DSP, запрет `android.*` в JVM-модулях, lint) и debug-APK как артефакт; на тег `v*` — release-APK и GitHub Release с заметками из `CHANGELOG.md`. Выпуск версии: поднять `versionCode`/`versionName` в `app/build.gradle.kts`, дописать `CHANGELOG.md`, `git tag vX.Y.Z && git push --tags`.

Подпись release: релизы подписываются постоянным ключом из секретов репозитория `CUPOLA_KEYSTORE_B64` (keystore в base64), `CUPOLA_KEYSTORE_PASSWORD`, `CUPOLA_KEY_ALIAS`, `CUPOLA_KEY_PASSWORD`, без секретов — debug-ключом раннера (такой APK ставится, но обновление поверх сборки с другим ключом потребует переустановки). Keystore создаётся один раз: `keytool -genkeypair -v -keystore cupola.jks -alias cupola -keyalg RSA -keysize 4096 -validity 10000`, затем `base64 -w0 cupola.jks` → секрет. Локально те же переменные окружения подхватывает `./gradlew :app:assembleRelease`.

## Известные ограничения (SPEC §13)

- Пороги купола (доля %, возвышение dB) общие для всех и подбираются в advanced-настройках; сравнивать себя стоит только с собой — микрофон, расстояние и комната меняют числа.
- Певческая форманта формируется месяцами; отсутствие роста за неделю — норма.
- Высокий «звон» можно получить и зажатым звуком; гейты отсекают это лишь частично. Окончательный судья — преподаватель и ощущение свободы горла.
- Твэнг и носовой звук тоже поднимают энергию около 3 кГц; приложение не отличает их надёжно.
- На части устройств `UNPROCESSED` отсутствует, а `VOICE_RECOGNITION` реализован с отклонениями; в настройках есть переключатель источника, состояние обработки описано в пояснении к «Обработке звука».
- Детектор высоты — YIN с гребенчатым трекером гармоник: на записях с оркестром и через динамики возможны кратковременные октавные промахи. CPPS/HNR и связанные гейты — в следующих версиях.
